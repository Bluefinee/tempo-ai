## 決定記録

### 2026-01 React Native (Expo) への移行

#### コンテキスト
iOS ネイティブ (SwiftUI) から React Native への移行を決定。

#### 選択肢
1. SwiftUI 継続 - iOS のみ、ネイティブパフォーマンス
2. React Native (Expo) - クロスプラットフォーム、開発速度向上
3. Flutter - クロスプラットフォーム、学習コスト

#### 決定
React Native (Expo) を選択。

理由:
- 将来的な Android 対応を見据える
- TypeScript での統一（バックエンドと同一言語）
- Expo による開発体験の向上
- 既存の React エコシステムの活用

#### 結果
- 開発速度が向上
- コードベースが TypeScript に統一
- HealthKit 統合は react-native-health で対応

### 2026-01 データベースレスアーキテクチャ

#### コンテキスト
ヘルスデータの保存方法を決定。

#### 選択肢
1. サーバー側 DB (PostgreSQL) - 中央集権、バックアップ容易
2. デバイス内のみ (AsyncStorage) - プライバシー最優先

#### 決定
デバイス内のみに保存（データベースレス）。

理由:
- プライバシーファーストの設計原則
- GDPR/HIPAA 準拠の簡素化
- サーバーコスト削減
- オフラインファースト対応

#### 結果
- ユーザーのヘルスデータはサーバーに送信されない
- AI アドバイス生成時のみ、匿名化されたサマリーを送信
- Cloudflare Workers は DB レスで運用

---

### 2026-01 Claude API の選択

#### コンテキスト
AI アドバイス生成に使用する LLM を選択。

#### 選択肢
1. OpenAI GPT-4 - 広く使われている
2. Anthropic Claude - 安全性重視、キャッシュ機能
3. Google Gemini - Google エコシステム統合

#### 決定
Anthropic Claude API を選択。

理由:
- System prompt のキャッシュ機能でコスト削減
- ヘルスケアコンテンツに適した安全性設計
- 日本語の品質が良好

#### 結果
- トークン効率が向上（キャッシュにより ~50% コスト削減）
- 1リクエストあたり約 $0.03
